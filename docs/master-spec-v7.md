# ระบบจ่ายชุดเครื่องมือ รุ่น 7

อ้างอิง Master Spec ที่เจ้าของโครงการส่งวันที่ 29 ตุลาคม 2569 ใช้แทนแนวทางคำถามและผลลัพธ์รุ่นก่อนหน้า

## คำถามและการจับคู่

ถาม 4 ข้อเรียง พื้นที่ → บทบาท → กลุ่มเยาวชน → เป้าหมาย ทั้งหมดเลือกข้อเดียวแล้วไปต่อ ไม่มีคำถามระยะเวลา ไม่มีปุ่มยืนยันแยก ไม่มี AI สร้างคำแนะนำสด

แท็กใช้ตามบรีฟ `setting_*`, `role_*`, `youth_*`, `goal_c1`–`goal_c5` และจับคู่ครบทั้งสี่ค่า ต้องตรงเพียงหนึ่งแถวจึงสร้างแผนได้ ย้อนกลับแล้วคำตอบถัดไปถูกล้าง เพื่อไม่ให้ติดคำตอบเก่า

- 625 ชุดคำตอบที่เป็นไปได้ จับคู่ได้ 176 ชุด และยังไม่มีไฟล์ที่ตรง 449 ชุด
- 10 แพ็กเกจตามพื้นที่/เป้าหมาย มีชุดไฟล์ที่ต่างกัน 15 แบบ
- ใช้เครื่องมือหลัก 18 ชิ้น ต้นฉบับ 30 ไฟล์ เครื่องมือเสริม 21 ชิ้นยังเป็นรายการรอไฟล์ ไม่สร้าง URL หรือไฟล์สมมติ
- ช่วงจำนวน 3–5 ชิ้นเป็นเป้าหมายเมื่อมีไฟล์จริงที่เหมาะสม บางเส้นทางได้ 1–2 ชิ้น และระบุจำนวนจริง ไม่ใช้เอกสารองค์ประกอบเติมจำนวน
- บทบาทและกลุ่มเป้าหมายใหม่กว้างกว่าเดิม จึงมีเงื่อนไขไม่จับคู่บางกรณี: เด็กปฐมวัยกับงานแกนนำ, เด็กเล็กกับงานช่วยเลิก, คู่มือคนทำงานกับนักเรียน, และการใช้คู่มือวิชาชีพโดยบทบาททั่วไป
- กลุ่ม 0–6 ปีไม่เท่ากับเครื่องมือครอบคลุมทุกวัย: กำชับตรวจช่วงวัยในต้นฉบับและไม่ใช้สื่อกับวัย 0–2 ปีโดยอัตโนมัติ
- กลุ่มเสี่ยง/ชาติพันธุ์/นอกระบบเป็นกลุ่มรวม รายงานชาติพันธุ์จึงอยู่ในข้อมูลประกอบ ไม่อ้างว่าเป็นแบบประเมินหรือใช้แทนทุกกลุ่ม

ตารางปัจจุบัน: [เส้นทางที่จับคู่ได้](../presets/real-tools-v2/presets.csv), [คำตอบทั้งหมดรวมช่องว่าง](../presets/real-tools-v2/all-paths.csv), [บัญชี 39 รายการ](../presets/real-tools-v2/tool-registry.json)

## ผลลัพธ์และไฟล์ส่งออก

หน้าผลลัพธ์มี 6 ส่วน: สรุปบริบทจากคำตอบจริง, ชุดเครื่องมือ, แผนลำดับ 1–2–3, แนวทางดำเนินงานสามหัวข้อ, ปุ่ม PDF/ZIP, และแบบประเมิน 1–5 ดาวพร้อมข้อเสนอแนะ

บรีฟใหม่นี้เพิ่มข้อควรระวังกลับมาโดยชัดเจน จึงใช้ `implementationGuidance` ที่ระบุต้นทาง `user_master_brief_2026_10_29` แทนข้อมูลคำแนะนำอัตโนมัติที่ถอนในรุ่น 6 ข้อความเป็นคงที่จากบรีฟและแผนเดิม ไม่มีการวนคำแนะนำ ไม่มีการรับรองว่าเป็นเนื้อหาตรวจโดยผู้เชี่ยวชาญใหม่ เลขอ้างอิง [1]–[13] ในบรีฟไม่ได้เป็นเอกสารที่ตรวจได้ จึงไม่แสดงเป็น citation บนหน้าเว็บ

มาตรฐานความสำเร็จใช้ผลเชิงกระบวนการที่ทีมตรวจได้ ไม่รับประกันผลลดการสูบ การคัดกรองทางคลินิกและการรักษาต้องดำเนินงานโดยผู้ประกอบวิชาชีพ อสม. และผู้ประสานไม่มีบทบาทวินิจฉัยหรือสั่งยา

PDF คง A4 แนวนอน หัวเรื่องน้ำเงิน กล่องเครื่องมือเขียว/พีช และแถบลำดับสีฟ้า เพิ่มแนวทางที่ได้รับในบรีฟลงด้านล่างโดยตรวจให้จบหน้าเดียว ไม่รวมแบบประเมินลง PDF

ZIP ชื่อ `ชุดเครื่องมือสำหรับคุณ.zip` ใช้ต้นฉบับ ≤6 MB จาก Supabase Storage และไฟล์ใหญ่เป็นลิงก์ Google Drive ใน TXT คู่มือเริ่มใช้ถูกปรับให้ตรงกับแผนของผู้ใช้ก่อนดาวน์โหลด ไฟล์เครื่องมือต้นฉบับไม่แก้ไข

กรณีไม่มีชุดเครื่องมือ: แสดงบริบทและเหตุผล ไม่เปิดปุ่มส่งออก เสนอเฉพาะเป้าหมายอื่นที่มีไฟล์จริงสำหรับพื้นที่/บทบาท/กลุ่มเยาวชนเดียวกัน

## การบันทึกผลประเมิน

`POST /api/feedback` บันทึก JSON ใน bucket ส่วนตัว `plan-feedback` ของ Supabase Storage ผ่าน server service key เท่านั้น ไม่มีสิทธิ์ public read/write ไม่มีการอัปโหลดจาก browser โดยตรง ไม่เก็บอีเมล ชื่อ IP หรือ user agent

แต่ละหน้าแผนออก token ลงลายเซ็น HMAC ผูกกับ release และ scenario อายุ 24 ชั่วโมง ใช้ nonce เป็นชื่อไฟล์ ส่งซ้ำจากหน้าเดิมไม่สร้างข้อมูลซ้ำ เก็บคะแนน 1–5 ข้อเสนอแนะ ≤1,000 ตัวอักษร และเวลาบันทึก ตรวจ Origin, ประเภทเนื้อหา, ความยาว และลายเซ็นก่อนบันทึก

เมื่อบันทึกล้มเหลวให้ retry ได้โดยคงคะแนนและข้อความ ไม่ขึ้นข้อความสำเร็จก่อน Supabase ตอบรับ ตาราง feedback ใน database.md เป็นงานระยะถัดไป; รุ่นนี้ใช้ private Storage เพื่อบันทึกจริงโดยไม่แก้โครงสร้างตารางสมาชิกหรือ RLS ที่มีอยู่

## สร้าง ตรวจ และเผยแพร่

1. `node scripts/build-intervention-presets.mjs`
2. `node --env-file=.env.local scripts/release-real-tools.mjs --stage --preset=presets/real-tools-v2/presets.json`
3. เปิดแอปเฉพาะเครื่องด้วย `CONTENT_PREVIEW_VERSION=real-tools-2026-10-29-v7` แล้วรันทดสอบ `scripts/test-master-spec.mjs`
4. เผยแพร่โค้ดเข้า main/draft ด้วย Git ตามเดิม ไม่ล็อกอินผ่าน GitHub CLI แล้วรอ Vercel build
5. `node --env-file=.env.local scripts/release-real-tools.mjs --verify --preset=presets/real-tools-v2/presets.json`
6. `node --env-file=.env.local scripts/release-real-tools.mjs --publish --preset=presets/real-tools-v2/presets.json`
7. ตั้ง `TEST_BASE_URL=https://ai-somking-chatbot.vercel.app` แล้วตรวจ flow และดาวน์โหลดอีกครั้ง

รุ่นเก่าและไฟล์ต้นฉบับไม่ถูกเขียนทับ checkpoint สำหรับย้อนกลับอยู่ใน `.prd-analysis/real-tools-2026-10-29-v7-release.json` ใช้คำสั่ง `--rollback --preset=presets/real-tools-v2/presets.json` เพื่อคืน active pointer ส่วน frontend ยังรองรับ flow รุ่น 6 ระหว่างสลับข้อมูลและการกู้คืน

## ผลตรวจรุ่นนี้

- Source matrix ครบ 625 ชุดคำตอบ ไม่มีแถวกำกวม และต้นฉบับ 30 ไฟล์ตรง hash เดิม
- ตรวจ PDF จริงทั้ง 15 รูปแบบชุดไฟล์ จบหน้าเดียวและมีแนวทางครบสามหัวข้อ
- ทดสอบ browser มือถือครบ 5 พื้นที่ เลือกย้อนกลับได้ คำถามปัจจุบันมองเห็น ไม่มีปุ่มยืนยัน และไม่มีเนื้อหาล้นแนวนอน
- ดาวน์โหลด ZIP จริงครบ 5 พื้นที่ ตรวจ CRC/hash ไฟล์เล็กและลิงก์ไฟล์ใหญ่ ไม่มีเอกสารองค์ประกอบถูกนำมาแจก
- ทดสอบแบบประเมิน: ไม่เลือกคะแนน, ส่งล้มเหลวแล้ว retry, บันทึกจริง, ส่งซ้ำ, ลายเซ็นปลอม, คะแนนนอกช่วง, Origin ต่างเว็บ และ anon อ่านไฟล์ผลประเมินไม่ได้ รายการทดสอบถูกลบหลังตรวจ
- ตรวจภาพ desktop/mobile และ PDF จริง Artwork หลักเดิมยังอยู่ แถบซ้ายสีน้ำเงิน 4px ใช้ตามตัวอย่างที่ Master Spec ระบุโดยตรง จึงคงไว้แม้ detector จะแจ้งรูปแบบ side-tab

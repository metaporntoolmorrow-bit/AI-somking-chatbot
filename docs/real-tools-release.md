# การเผยแพร่ชุดเครื่องมือจริง

ชุดข้อมูล: `real-tools-2026-10-26-v2` — 5 พื้นที่, 7 แพ็กเกจ, 18 เครื่องมือ, 102 เส้นทางคำตอบ

รุ่นนี้รวมเป้าหมายที่เคยได้ไฟล์ชุดเดียวกันเป็นแพ็กเกจเดียว ทุกเส้นทางมีเครื่องมืออย่างน้อย 2 รายการ พร้อมลำดับการใช้ สิ่งที่อยากได้ ข้อควรระวัง และแนวทางการใช้ประโยชน์ ลำดับเป็นข้อเสนอประกอบที่จัดทำเพิ่มตามคำขอ ไม่ได้สร้างคำสั่งรักษาหรือขนาดยา อ่านเหตุผลและการรวมเป้าหมายใน `presets/real-tools-v1/package-review.md`

เก็บคำตอบที่ใช้จับคู่ครบ 5 ด้าน โดยแสดง 4 คำถามหลักตามลำดับ พื้นที่ → บทบาท → เรื่องที่อยากเริ่มทำ → กลุ่มเป้าหมาย ส่วนคำถามป้องกัน/ดูแลคนที่ใช้อยู่แล้วแสดงเฉพาะเมื่อมีหลายตัวเลือก ทุกเส้นทางปัจจุบันอนุมานค่านี้จากเรื่องที่เลือกได้ กลุ่มเป้าหมายเลือกได้หลายข้อและมีปุ่มยืนยัน ข้ออื่นเลือกแล้วไปต่อทันที

## แหล่งข้อมูลและไฟล์

- กฎต้นทาง: `presets/real-tools-v1/source-rules.mjs`
- การประกอบชุดและลำดับ: `presets/real-tools-v1/package-playbooks.mjs` (ชื่อโฟลเดอร์เดิม แต่ version label เป็น v2)
- ข้อมูลที่ตรวจสอบแล้ว: `presets/real-tools-v1/presets.json`
- ไฟล์ขนาดไม่เกิน 6,000,000 ไบต์ 10 ไฟล์: Supabase Storage ถังส่วนตัว `real-tool-assets`
- ไฟล์ขนาดใหญ่: Google Drive 25 ลิงก์ที่ตรวจสิทธิ์ `anyone:reader` แล้ว รวมสำเนาคู่มือขนาดใหญ่ที่แบ่งครบ 224 หน้า
- ZIP สร้างล่วงหน้า 28 ชุดที่ไม่ซ้ำ ครอบคลุมการเลือกกลุ่มเป้าหมาย 827 แบบ มี `00-เริ่มใช้แพ็กเกจ.txt` พร้อมลำดับ ข้อควรระวัง และการใช้ประโยชน์ ไฟล์ต้นฉบับเล็กอยู่ในโฟลเดอร์ที่เรียงตามการใช้ครั้งแรก ไฟล์ใหญ่เป็นลิงก์ใน TXT รวมไฟล์ที่หลายกลุ่มใช้ร่วมกันเพียงครั้งเดียว
- แผน PDF รวมทุกกลุ่มที่เลือกใน A4 แนวนอนหน้าเดียว อ้างอิง artwork `ไฟล์ภาพผลลัพธ์เมื่อกดดาวน์โหลดแผน PDF.jpg` ใช้ลำดับเครื่องมือ ข้อควรระวัง และแนวทางการใช้ประโยชน์ ไม่มีหน้ารายละเอียดต่อท้ายหรือแผนรายสัปดาห์
- เครื่องมือเสริม 21 รายการที่ยังไม่มีไฟล์ไม่ถูกนำมาอ้างว่าดาวน์โหลดได้

ไฟล์ต้นฉบับและไฟล์ทดสอบไม่ขึ้น Git/Vercel ใช้ Storage และ Drive สำหรับไฟล์จริง API ตรวจแผนและกลุ่มที่เลือกก่อนออกลิงก์ Storage อายุ 5 นาที แล้วเปลี่ยนทางให้ดาวน์โหลดจาก Storage โดยตรง

## ชื่อ ZIP และชุดคำแนะนำ 20 ชุด

- ชื่อที่ผู้ใช้ได้รับคือ `ชุดเครื่องมือสำหรับคุณ.zip` เว็บอ่าน ZIP จาก signed Storage โดยตรง แล้วกำหนดชื่อภาษาไทยผ่าน Blob download จึงไม่ต้องส่งไฟล์ใหญ่ผ่านขีดจำกัด response ของ Vercel
- ก่อนบันทึก ZIP เว็บปรับเฉพาะ `00-เริ่มใช้แพ็กเกจ.txt` ให้ตรงกับหน้าผลลัพธ์และ PDF ไฟล์ต้นฉบับ ลิงก์ Drive และลำดับโฟลเดอร์อื่นคงเดิม
- คลังคำแนะนำ: `src/content/package-guidance.json` มี 20 ชุดที่จัดทำเพื่อช่วยดำเนินกิจกรรม ไม่ใช่การเปลี่ยนเนื้อหาทางคลินิกหรือการจับคู่เครื่องมือใน Supabase อ่านฉบับตรวจข้อความได้ใน `presets/real-tools-v1/guidance-sets.md`
- การยืนยันคำตอบครั้งสุดท้ายของแชทบอตจะเลือกชุดถัดไป เก็บเพียงตัวนับ `package-guidance-cycle-v1` ใน localStorage ของเบราว์เซอร์นั้น ครบ 20 แล้ววนกลับชุดแรก หากใช้ storage ไม่ได้จะวนในหน่วยความจำระหว่างการใช้งานนั้น
- เลขชุดอยู่ในพารามิเตอร์ `guidance` ของ URL เดิมจึงเปิดซ้ำได้ข้อความเดิม การรีเฟรชหรือกดดาวน์โหลดไม่ใช้โควตาชุดใหม่ ลิงก์เก่าที่ไม่มีเลขชุดและเลขที่ไม่ถูกต้องใช้ชุด 1
- ข้อจำกัดเฉพาะเครื่องมือ เช่น รายงานที่ไม่ใช่แบบประเมิน คู่มือโรงเรียนที่ต้องปรับในอุดมศึกษา และขอบเขตวิชาชีพบริการสุขภาพ ไม่ถูกสุ่มออก
- ตรวจด้วย `node scripts/test-guidance-downloads.mjs` ครอบคลุมการตอบแชทบอตเดิม 21 ครั้ง การวนไม่ซ้ำในรอบ 20 ชุด PDF หน้าเดียวทุกชุดในบริบทที่มีขั้นตอนมากที่สุดและบริการสุขภาพ ชื่อ ZIP ที่เบราว์เซอร์บันทึกจริง ความตรงกันของคำแนะนำ และ hash ของไฟล์ต้นฉบับใน ZIP ทั้ง 5 พื้นที่

## ขั้นตอนนำเข้าและตรวจสอบ

ต้องตั้ง `.env.local` ให้มี URL, public key และ server secret ของ Supabase ห้ามส่ง server secret ไปเบราว์เซอร์

```powershell
node scripts/build-real-tool-presets.mjs --require-drive --require-public
node --env-file=.env.local scripts/release-real-tools.mjs --stage
$env:CONTENT_PREVIEW_VERSION='real-tools-2026-10-26-v2'
npm.cmd run dev
# อีก terminal
node scripts/test-real-tools.mjs
node --env-file=.env.local scripts/release-real-tools.mjs --verify
npm.cmd run lint
npm.cmd run build
```

`CONTENT_PREVIEW_VERSION` ใช้เฉพาะเครื่องทดสอบฝั่งเซิร์ฟเวอร์เพื่อดูฉบับร่าง ห้ามตั้งใน Production การดูเว็บปกติอ่านชุดข้อมูลที่เผยแพร่และ active ผ่านสิทธิ์สาธารณะเดิม

ตรวจ PDF หลังแก้ artwork ด้วย `node scripts/test-pdf-artwork.mjs` ซึ่งใช้ Edge และ Poppler (`pdfinfo`) ตรวจทั้ง 31 บริบทเมื่อเลือกทุกกลุ่มในบริบทนั้นว่าจบในหน้าเดียว รวมถึงตรวจปุ่ม PDF และเปรียบเทียบภาพหน้าจอมือถือ/คอมกับ baseline ก่อนแก้ หากยังไม่มี baseline ให้รัน `node scripts/test-pdf-artwork.mjs --baseline` กับเวอร์ชันก่อนแก้ก่อน ไฟล์ทดสอบอยู่ใน `output/qa/pdf-artwork/` และไม่ขึ้น Git

เผยแพร่โค้ดที่รองรับชุดใหม่ก่อน แล้วจึงสลับข้อมูล:

```powershell
node --env-file=.env.local scripts/release-real-tools.mjs --publish
$env:TEST_BASE_URL='https://ai-somking-chatbot.vercel.app'
node scripts/test-real-tools.mjs --smoke
```

การเผยแพร่เก็บผู้อนุมัติ เวลา และบันทึกการเปลี่ยนแปลงในฐานข้อมูล การอนุมัติหมายถึงเจ้าของโครงการอนุมัติให้นำขึ้นเว็บ ไม่ใช่การรับรองทางการแพทย์ แหล่งที่มาและส่วนของกฎที่จัดทำเพิ่มเติมยังเก็บอยู่ใน `source_payload`

## การย้อนกลับ

ตัวนำเข้าจะไม่เขียนทับ release หรือไฟล์รุ่นเก่า และไม่อนุญาต stage ทับรุ่นที่เผยแพร่แล้ว เก็บค่า active ก่อนเปลี่ยนไว้ใน `.prd-analysis/real-tools-2026-10-26-v2-release.json` ซึ่งไม่ขึ้น Git

```powershell
node --env-file=.env.local scripts/release-real-tools.mjs --rollback
```

คำสั่งนี้คืนค่า active เดิม โดยเก็บข้อมูลและไฟล์รุ่นใหม่ไว้ตรวจสอบ หากแก้เนื้อหาในอนาคตให้ใช้ version label ใหม่ นำเข้าและทดสอบก่อนสลับอีกครั้ง ส่วนระบบสมาชิกและการเข้าสู่ระบบไม่เกี่ยวกับกระบวนการนี้
